# 校园知识库系统使用手册

## 系统概述

校园知识库系统是一个面向高校师生的智能问答平台，旨在将分散在各个部门的教学文档、管理制度和技术资料统一整合。系统支持上传纯文本格式的资料文件，上传后自动完成数据清洗、语义切片和向量入库三个阶段。用户在提问时，系统会先从向量库中召回与问题语义最相关的切片，再交给大语言模型生成最终回答。整个过程对用户透明，回答中还会附上引用来源，方便追溯原文出处。

## 系统架构

系统采用前后端分离架构。后端基于 Spring Boot 构建，负责文件接收、文本处理与检索编排。向量数据库选用 Milvus，负责存储文档切片的向量表示，并提供高效的相似度检索能力。嵌入模型将文本转换为高维向量，当前使用的模型输出维度为 1024 维。切片算法基于相邻句子的语义相似度：当相邻句子的向量相似度低于阈值时断开成块，同时保证每个块的字符长度落在最小值与最大值之间。过小的块会被并入后续块，以避免碎片化影响检索质量。

## 数据清洗流程

数据清洗是切片前的关键步骤。清洗器会先把整篇文档切分为正文、表格和代码块三类结构化分段。正文与表格中的英文单词会被统一转为小写，以提升检索召回率，但链接地址保持原样，因为路径大小写敏感。显式的目录标题区会被整体过滤，防止目录条目混入正文切片。表格切片不做语义拆分，而是按行边界打包，保证表格结构完整；单个超长行才会被硬性切分。

## 切片参数说明

系统提供以下可配置参数：

- 相似度阈值：相邻句子向量相似度的断开阈值，默认 0.7。
- 最小块长度：低于该长度的块会被向后合并，默认 50 字符。
- 最大块长度：超过该长度的块会被强制断开，默认 1000 字符。
- 嵌入批大小：每次送入嵌入模型的句子数量，默认 32 句。
- 策略版本：切片流水线的版本号，版本变化会触发同文档的切片重建。

## 功能对照表

| 功能模块 | 说明 | 默认值 |
| --- | --- | --- |
| 语义切片 | 基于句子向量相似度切分正文 | 阈值 0.7 |
| 原子切片 | 表格与代码按行打包 | 最大 1000 字符 |
| 目录过滤 | 移除显式目录标题区 | 开启 |
| 英文小写化 | 正文与表格单元格归一 | 开启 |
| 查重跳过 | 相同文档与策略版本不重复导入 | 开启 |

```java

public SemanticTextSplitter semanticTextSplitter(EmbeddingModel embeddingModel,
                                                 ChunkingProperties chunkingProperties) {
    return new SemanticTextSplitter(embeddingModel, chunkingProperties);
}
```

## 检索与召回

检索服务接收用户问题后，先调用嵌入模型把问题转为向量，再到 Milvus 中执行相似度搜索。召回条数由参数 top_k 控制，默认取 8 条，同时设置相似度下限 0.5，低于下限的结果会被丢弃。被召回的切片会连同文件名、块序号和相似度分数一起返回给上层服务。上层服务把切片内容拼装进提示词，引导模型基于给定材料作答，从而减少凭空编造。若召回结果为空，系统会退化为普通多轮对话，仍然保证用户得到响应。

## 常见问题

导入文件失败通常有三类原因。第一类是文件格式不符，系统目前只接受纯文本文件，其他格式会直接返回错误。第二类是文件内容为空，空文件没有切片价值，同样会被拒绝。第三类是重复导入，内容完全相同的文件通过内容摘要识别，直接跳过以节省向量库空间。

检索结果不理想时，可以从两个方向调整。一方面提高召回条数，让更多候选切片进入提示词；另一方面降低相似度下限，放宽召回门槛。二者都会增加模型上下文长度，需要权衡回答质量与推理开销。

## 术语约定

知识库中把一段连续的文本片段称为切片。切片是检索的最小单元，每个切片携带文件名、块序号、块总数与内容摘要等元数据。把切片组织成语义连贯的块有助于提高回答的准确性，因此切片算法需要在语义完整性与长度约束之间取得平衡。文档导入后会生成唯一的摘要标识，相同标识与相同策略版本的文档不会重复入库，策略版本升级后重新导入即可完成切片重建。

## 运维提示

向量库服务建议以容器方式部署，配合固定端口与持久化存储卷。升级切片策略前应先记录当前基线指标，包括切片总数、平均长度与碎块率，升级完成后对比指标变化，确认新策略没有引入明显退化。若需要回滚，只需把策略版本号恢复为旧值并重新导入历史文件。

## 权限与安全

知识库按部门划分可见范围，上传者默认对自己部门可见，跨部门共享需要管理员审批。文件在上传时即计算内容摘要，摘要既是查重的依据，也是切片元数据的一部分，用于把同一文档的所有切片关联起来。日志系统会记录每次检索命中的文件名与相似度分数，便于事后审计召回质量。敏感词过滤在清洗阶段完成，命中敏感词的段落会被整段丢弃，避免进入向量库后被召回。

## 性能观察

在普通办公电脑上，一篇一万字左右的文档从上传到完成入库通常在数秒内完成，其中嵌入计算占大头。批量送入嵌入模型可以显著减少请求次数，批大小过小会造成频繁往返，过大则可能触发上游接口的超时保护。检索阶段的耗时主要集中在向量搜索与提示词拼装，通常在百毫秒级别。若出现明显的性能退化，应优先检查嵌入服务是否可用，其次检查向量库的集合是否发生碎片化。

## 版本历史

初始版本实现了基础的固定长度切片，按字符数硬性切分，不考虑语义边界。第二个版本引入句子边界识别，切片不再把一句话从中间截断，但仍按固定长度合并。当前版本使用向量相似度判断语义断点，只有当相邻句子相似度低于阈值时才断开，块长度约束仅作为兜底保护。后续版本计划引入标题感知能力，让章节标题成为天然的切片边界，并把表格标题与表格内容绑定在同一个切片里。

## 评测方法

评测切片质量需要一套可复现的固定语料。语料应当覆盖标题、正文、列表、表格、代码块和链接等全部版式元素，并包含长度分布各异的句子，这样才能真实反映切片算法在各种输入下的行为。评测指标至少包括切片总数、最小长度、最大长度、平均长度与碎块率。碎块率定义为长度低于一百字符的切片占比，碎块过多说明最小长度合并没有发挥作用。每次调整切片参数或升级策略版本后，都要在固定语料上重新跑一遍评测，把新旧指标放在同一张表里对比。只有当平均长度保持稳定且碎块率没有上升时，才能认为新策略没有退化。评测通过的策略才可以发布到生产环境，并同步更新文档中的参数说明。基线语料与评测脚本一并纳入版本管理，保证任何人在任何时间复现出的指标完全一致。
